기록 항목 (로그)

판을 돌리면서 남기는 값과 대시보드에서 쓰는 곳. 지금 코드(prototype/core, dashboard/sim.js)가 실제로 남기는 것 기준. 처음엔 없다가 새로 더한 것은 4번에 따로 모음.

기록은 두 겹.

  • 사건 기록: 판이 도는 동안 맞음, 적 처치, 카드 선택 같은 일이 생길 때마다 한 줄. 다시 보기와 판 요약의 재료
  • 판 요약: 판이 끝나면 사건 기록을 훑어서 한 줄로 줄인 것. 대시보드는 이 요약만 모아서 그래프를 그림

모든 사건에는 시각(초), 층, 웨이브가 같이 붙음.

1. 판이 끝나는 방식

결과언제대시보드에서
사망체력이 0이 됨실력별 결과 막대, 어디서 죽었나
클리어5층을 깸(무한 모드 들어가기 전에 끝냄)실력별 결과 막대
시간 초과한 층(보스 포함) 전투 시간이 120초를 넘음실력별 결과 막대, 튀는 판으로 바로 짚음

사망과 시간 초과는 따로 셈. 둘 다 못 깬 판이지만 원인이 반대(너무 약함 / 너무 오래 걸림)라, 합치면 조정 방향을 잘못 읽게 됨.

4. 새로 더한 것 (11/21)

처음 정리할 때 없던 4개를 대시보드 판 요약에 더함. 더한 뒤 실력별 시드 1~200을 다시 돌렸고, 클리어, 사망, 시간 초과 수가 전과 같았음(11/21 값 기준 숙련 151/0/49, 중간 194/3/3, 초보 107/93/0). 기록만 늘린 거라 게임 결과는 그대로.

11/22에 값이 바뀐 뒤(치명타 10%, 대시 쿨 1초, 슈퍼아머 30, 돌진 예고 2.5초) 같은 시드 결과: 숙련 179/0/21, 중간 200/0/0, 초보 169/31/0.

항목판 요약 이름남기는 값왜 필요한가
한 방에 크게 맞은 피해maxHit한 번에 받은 가장 큰 피해한 번에 큰 피해를 받은 판을 튀는 판으로 짚기
보스 휘두르기 / 돌진 구분hitBy, hitN, atkN의 slam, charge공격별 받은 피해 / 맞은 횟수 / 나온 횟수초보는 돌진만 피한다는 봇 실력 검사
누구한테 죽었나deathBy죽기 직전 마지막으로 맞은 공격(근거리형, 원거리형, 휘두르기, 돌진). 안 죽었으면 비움죽은 원인별로 보기
층마다 나온 맵maps층 순서대로 나온 맵맵별 결과 비교
  • 공격 종류는 게임이 "플레이어가 맞음" 사건에 직접 남김(attack: melee, ranged, slam, charge). 보스는 휘두르기와 돌진을 때릴 때 각각 넘기고, 일반 몹은 근거리 공격과 투사체에서 넘김. 예전처럼 넉백 배율로 짐작하지 않아서, 두 배율이 같아져도 안 깨짐
  • 프로토타입까지 고친 건 직접 결정(11/21). 고치기 전과 판마다 비교해서 600판 모두 끝난 이유, 전투 시간, 공격별 맞은 횟수, 죽은 원인이 같은 걸 확인(프로토타입 메모 35번)
  • 죽은 원인(11/22 값): 사망은 초보 31판뿐이고 전부 휘두르기. 11/21 값에서는 중간 사망 3판 전부 휘두르기, 초보 사망 93판은 휘두르기 91, 돌진 1, 근거리형 1
  • 맵은 지금 전부 M001이라, 맵별 비교는 맵이 늘어나야 의미가 생김

환경 조건(data/env.js)은 아직 게임에 없어서 기록할 것 없음. 들어가면 웨이브 시작 사건과 판 요약에 같이 남김.

5. 저장과 불러오기

지금 대시보드(dashboard/app.js)에 있음.

  • 브라우저 임시 저장: 조정판으로 돌린 조건은 보는 사람 브라우저에 최근 10개까지. 저장 공간이 모자라면 최근 3개만
  • JSON 다운로드: 돌린 조건들(조정값, 판 수, 판 요약 전부)을 dashboard-conditions.json 파일 하나로 받기
  • 불러오기: 받은 파일을 다시 올리면 조건 목록에 붙음
  • 기본 데이터: DT 문서 값(11/22)으로 실력별 200판(시드 1~200)을 미리 돌려서 base.js에 넣어 둠. 만드는 스크립트는 gen.js

6. 바뀔 수 있는 것

  • 대시보드 검사 규칙의 맞음 범위가 아직 안 정해짐. 정해지면서 새로 재야 할 값이 생기면 판 요약 항목이 늘어남
  • 1맵 일반 웨이브 수는 지금 4개(체감 기준, 3과 4 사이에서 일단 4)라 3개와 비교할 수 있음. 웨이브별 걸린 시간과 실력별 생존이 이미 남고 있어서 기록 쪽은 따로 바꿀 것 없음
