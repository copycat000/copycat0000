액션 로그라이트 통합 기획서 – 큰 틀

2026.11.20 / 타디온

기획은 여섯 파트로 나눠 문서를 따로 썼습니다. 콘셉트와 테마, 시스템, 콘텐츠(레벨, 보스), DT, 로그, 대시보드입니다.

문서끼리 내용이 엇갈리지 않게, 바꾸지 않을 것과 파트별 범위를 이 문서에 먼저 정했습니다. 작업 중 여기와 안 맞는 내용이 나오면 이 문서부터 고쳤습니다.

1. 어떤 게임인가

가라앉는 늪(가제). 던전 5개 층을 내려가는 액션 로그라이트입니다. 키보드로 이동, 대시, 공격만 하고, 층 순서는 판마다 바뀝니다.

핵심 재미

  1. 예측 안 되는 상황과 환경에 유연하게 대처하기
  2. 선택이 쌓여 빌드가 완성되는 성장 체감
  3. 키보드 조작 액션감

포트폴리오 전체 흐름을 기준으로 설계했습니다. 기획서에서 쌓고 대시보드에서 터뜨리는 구성이라 클라이맥스는 대시보드입니다. 뭔가를 넣을지 고민될 때는 "이게 대시보드에서 확인되나"를 먼저 봤습니다.

기획서에는 공식으로 계산한 의도 값을 적고, 대시보드에서 시뮬레이션 결과와 비교합니다. 어긋나면 수치를 고치고 다시 돌립니다. 이 한 바퀴가 보이게 하는 게 목표였습니다.

2. 처음에 정하고 바꾸지 않은 것

영역정한 내용
장르액션 로그라이트. 조작은 이동, 대시, 공격 정도
승패체력은 수치형. 맵 하나가 층 하나이고, 층마다 웨이브 5개 중 마지막이 보스. 여기까지가 코어 루프 한 바퀴. 5층을 깨면 클리어, 그 뒤로는 무한 모드로 계속 반복
의도: 클리어 뒤에도 계속 반복해서 돌 수 있게
맵미리 만든 맵 10개 중 5개가 무작위 순서로 나옴. 맵마다 웨이브 5개, 5번째는 보스
의도: 보스 전 일반 웨이브가 5번을 넘으면 루즈해지고, 2번이면 긴장감과 템포를 가져가기에 짧음. 3과 4 사이에서 일단 4로 두고 해 보면서 조정. 플레이 경험에서 나온 체감 기준
무작위 요소맵, 적 조합, 환경 조건, 업그레이드 후보, 봇의 반응 시간 흔들림과 업그레이드 선택. 모두 시드값에 묶여 있어서 같은 판을 그대로 다시 돌릴 수 있음
조작키보드만 사용. 8방향 이동이고 대각선으로 가도 속도가 같음. 기본 공격은 근접 부채꼴이고, 한 번 누르면 한 번 나감. 짧은 쿨타임이 있어서 쿨타임 감소를 쌓아도 끝없이 연타되지는 않음. 스킬 슬롯은 2칸. 대시 중에는 잠깐 무적
적몸에 닿기만 해서는 피해가 없고, 공격에 맞아야 피해를 입음. 공격 전에는 항상 예고 동작이 있음. 종류는 돌진형, 원거리형, 근거리형, 방해형(장판형, 디버프형, 적 회복형)
성장웨이브를 깰 때마다 카드 3장 중 1장을 고름. 경험치는 없음. 카드 갈래는 생존, 공격, 평타, 스킬(공격형, 유틸형)
스킬 슬롯2칸을 자유롭게 채움. 스킬을 얻으면 넣을 키를 고르고, 이미 찬 칸을 고르면 그 칸 스킬과 바뀜. 웨이브 사이에는 두 칸 위치를 바꿀 수 있음.
봇실력은 3단계. 예고 동작을 보고 대시를 누르기까지 걸리는 시간, 그리고 그 시간이 얼마나 들쭉날쭉한지로 나눔. 업그레이드 선택과 교체는 무작위. 숙련 봇에만 조건 규칙을 더 넣을 수 있음
테마검은 늪이 점점 뒤덮어 가는 어두운 던전. 주인공은 늪이 어디서 시작됐는지 찾으러 들어간 탐사대원이고, 내려갈수록 늪에 물들어 감. 자세한 내용은 콘셉트와 테마 문서에 있음
구조규칙 계산과 화면 그리기를 나눠서 만듦. 시뮬레이션은 브라우저(CPU)에서 돌리고 LLM은 쓰지 않음. 서버 없이 GitHub Pages에 올림

대시 쿨타임은 5초 안쪽에서 시작했고, 실제 값은 DT에서 시뮬레이션을 보며 맞췄습니다.

3. 판단이 갈릴 때 기준

기준이유
비교하려는 것 하나만 다르게, 나머지는 같게경험치를 뺀 것도 같은 이유. 잘하는 봇이 보상까지 더 받으면 실력별로 비교하기 어려워짐
실력 차이는 봇 3단계로 따로 보고, 같은 실력끼리는 기획 수치와 선택에 따라 결과가 갈리게그래서 새 요소를 넣을 때는 봇이 처리할 수 있는지부터 봄. 봇이 못 다루는 상황(예: 여러 발 날아오는 원거리 투사체)은 숙련 봇 규칙을 추가하거나 한계로 적어 둠
능력치와 계산식은 단순하게읽을 게 많으면 재미가 떨어진다는 걸 직접 겪어 봄. 대시보드에서 수치를 바꿨을 때 채용담당자도 바로 따라올 수 있어야 함
판끼리 영향 없게 (영구 성장 없음)판마다 따로 비교할 수 있어야 시뮬레이션 데이터가 의미 있음
맵과 웨이브는 미리 만들어 둔 단위로문제가 생긴 맵만 골라 고치고, 같은 시드로 다시 돌려서 확인하려고
본문에는 규칙과 의도만, 숫자는 DT에만숫자가 한 곳에 모여 있어야 대시보드 조정판과 바로 연결되고, 바꿀 때도 한 곳만 고치면 됨
의도는 확인할 수 있는 값으로"이렇게 될 거다"를 공식으로 계산한 값으로 적어야 시뮬레이션 결과와 맞춰 볼 수 있음. 값은 DT에 적음
키보드만, 마우스 조준 없음조준이 들어가면 실력을 가르는 요소가 하나 더 생김. 채용담당자가 터치패드로 열어 볼 수도 있음
브라우저 안에서만 돌아가게서버가 없고 시뮬레이션에 LLM을 쓰지 않으니, 서버나 토큰이 있어야 하는 기능은 넣지 않음

4. 파트별로 맡은 범위

파트다루는 것다른 파트로 넘기는 것
콘셉트와 테마게임 이름. 배경과 주인공, 적과 보스의 생김새와 분위기. 맵, 층, 적, 카드, 스킬 이름규칙, 숫자
시스템전투 규칙(공격, 대시, 피격, 무적). 일반 적 종류별 행동과 예고 동작, 디버프와 장판 종류. 보스 공통 규칙(보스 웨이브 시작과 끝, 체력바 UI, 예고 방식, 카운터나 파훼에 성공했을 때 처리, 페이즈 전환 방식). 카드 목록과 효과 규칙, 스킬 슬롯. 봇 행동 규칙. 무한 모드에서 5층 다음에 무엇을 반복할지. 화면 흐름과 UI어떤 맵에 무엇을 배치할지, 보스별 패턴, 숫자
콘텐츠 > 레벨맵 10개 구성, 웨이브 1~4의 적 조합, 환경 조건 목록, 보스 배치. 층이 올라갈수록, 무한 모드에서는 반복할수록 얼마나 어려워지는지일반 적 행동, 보스 공통 규칙, 숫자
콘텐츠 > 보스보스 수, 보스별 경험 의도, 패턴, 파훼 방법
의도: 보스가 없으면 판이 단조롭고, 일반 적은 2~3대면 죽어서 강해진 걸 체감할 상대가 없음. 보스마다 패턴, 공격, 경험이 달라서 시스템이 아니라 콘텐츠로 둠		일반 적 행동, 보스 공통 규칙, 숫자
DT모든 수치(캐릭터, 적, 보스, 카드, 스킬, 웨이브, 환경 조건, 봇 실력 3단계). 수치마다 의도 값과 그 계산식. 검사 규칙의 맞음 범위새 규칙이나 새 항목 추가
로그기록 항목 표(언제 / 어떤 값 / 대시보드에서 무엇을 보려고), 시뮬레이션 결과 저장 형식대시보드 화면 구성
대시보드화면 구성, 조정판에 올릴 수치 항목, 기획서 의도를 검사 규칙으로 바꾸는 방법, 결과가 어긋났는지 비교하는 방법, 그 밖에 더 보여줄 정보게임 규칙, 수치 값과 맞음 범위(DT), 기록 항목 정의(로그)

레벨과 보스는 목차에서 콘텐츠로 묶었고, 문서는 따로 있습니다. 대시보드 기획서는 게임이 의도대로 나오는지 검사하는 도구라서 맨 뒤에 따로 뒀습니다.

5. 파트끼리 넘겨준 것

주는 쪽받는 쪽넘기는 것
콘셉트와 테마전체맵, 층, 적, 카드, 스킬 이름 목록. 다른 파트는 이름을 새로 짓지 않고 이 목록을 씀
시스템콘텐츠일반 적 종류, 보스 공통 규칙, 환경 조건이 바꿀 수 있는 규칙. 콘텐츠는 이 안에서 맵을 짜고 보스 패턴을 만듦
시스템, 콘텐츠DT규칙마다 필요한 수치 항목 이름. 본문에는 값 대신 "DT: 항목명"으로 적음
시스템, 콘텐츠, DT로그의도 값마다 "대시보드에서 무엇으로 확인할지" 한 줄. 로그는 이걸 보고 기록 항목을 정하고, 확인할 의도가 없는 항목은 기록하지 않음
로그대시보드기록 항목과 저장 형식
DT대시보드조정판 수치의 기본값, 검사 규칙의 맞음 범위

범위 밖 얘기는 맡은 파트로 넘겼고, 2장이나 3장과 부딪히면 이 문서부터 고쳤습니다.
