대시보드 기획서

2026.11.21 / 이정헌

대시보드가 필요한 이유

밸런스 대시보드는 유니티 인스펙터처럼 수치를 바꾸고 바로 결과를 확인하는 화면입니다. 차이점은 사람이 직접 플레이하는 대신 봇이 수백 회 플레이하고, 그 결과를 기획서에 적은 의도와 비교한다는 점입니다.

기획서에는 "보스는 카드 없이 일정 시간 안에 처치된다(DT: 보스 체력)", "약한 봇은 시간 초과가 날 수 있다"처럼 의도가 값으로 적혀 있습니다. 실제로 그렇게 나오는지는 몇 번 플레이해서는 알 수 없습니다. 대시보드는 실력 3단계 봇으로 대량 시뮬레이션을 실행하고, 의도와 다르게 나온 부분을 숫자로 먼저 보여 줍니다.

범위

대시보드는 구조를 보여 주는 수준까지만 구현합니다. 수치 조정 패널에는 수치 6개와 플레이 횟수만 있습니다.

의도: 출시할 게임을 실제로 운영하는 것이 아니므로 구조만 보여 주면 된다.

게임 규칙, 수치 값(DT), 기록 항목 정의(작업 기록의 로그 기록 항목)는 이 문서에서 다루지 않습니다. 본문에는 값 대신 "DT: 항목 이름"만 적고, 예시 숫자는 현재 DT 값으로 실행한 결과입니다.

사용 흐름

문제 발견, 수치 조정, 재확인 과정이 화면 한 곳에서 이어집니다.

  1. 처음 열면 DT 기본값으로 미리 실행해 둔 결과가 표시됨
  2. 기획 의도 검증 칸에서 "불일치 N / 검증 M"을 먼저 확인. 누르면 불일치한 항목이 펼쳐짐
  3. 실력별 결과, 웨이브별 흐름 같은 다른 칸을 함께 보고 바꿀 수치를 정함
  4. 수치 조정 패널에서 값 하나를 바꾸고 다시 실행
  5. 실행 조건 목록에 한 줄이 추가되고, 직전 결과가 각 그래프에 흐리게 겹쳐 표시됨. 불일치가 줄었는지 바로 비교 가능

값은 한 번에 하나만 바꿉니다. 불일치 하나에 여러 수치가 함께 관련되어 있어서, 여러 개를 동시에 바꾸면 무엇 때문에 결과가 바뀌었는지 알 수 없기 때문입니다. 통합 기획서의 판단 기준 "비교하려는 것 하나만 다르게, 나머지는 같게"와 같은 원칙입니다.

의도: 조정에 필요한 근거 자료를 보여 주는 것이 대시보드의 목적이다.

모든 칸에 공통으로 들어가는 것

  • 봇 실력 설명: 숙련, 중간, 초보는 적의 예고를 보고 피하기까지 걸리는 반응 시간(DT: 봇 실력별 반응 시간)으로만 나뉘고, 카드는 무작위로 고름. 화면 위쪽에 표시
  • 플레이 횟수와 신뢰도: 그래프마다 몇 회 기준인지 표시하고, 플레이 횟수에 비해 차이가 작아 우연일 수 있는 값은 흐리게 표시. 신뢰구간 같은 통계 수치는 넣지 않음

결과가 크게 다른 플레이 자동 표시

기록을 하나하나 다시 확인하기 어려워서, 결과가 크게 다른 플레이는 대시보드가 자동으로 표시합니다. 같은 실력 안에서 혼자 너무 빨리 쓰러지거나 오래 버틴 플레이, 실력 순서가 뒤집힌 플레이, 한 웨이브가 유독 오래 걸린 플레이(봇이 끼었는지 확인용), 한 번에 큰 피해를 받은 플레이가 대상입니다. 기준은 상자 그림에서 상자 길이의 1.5배를 넘게 벗어난 값이며, 시간 초과된 플레이는 바로 표시합니다.

기획 의도 검증

시뮬레이션을 실행할 때마다 대시보드가 기획서의 의도를 자동으로 검증하고, "불일치 7 / 검증 10"처럼 결과를 숫자로 먼저 보여 줍니다. 의도 목록을 사람이 한 줄씩 읽는 방식은 쓰지 않습니다.

의도: 정해 둔 기획 의도를 확인만 하는 화면이면 번거롭기만 하다. 기획서의 문제를 먼저 찾아 주는 형태여야 쓸모가 있다. 예를 들어 A 조건에서 불일치 3개, B 조건에서 10개면 B가 더 나쁘다는 것이 바로 보여야 한다.

검증 규칙

시뮬레이션은 서버나 AI 없이 브라우저에서만 실행되므로 기획서 문장을 직접 읽지 못합니다. 그래서 기획서의 의도를 검증 규칙으로 바꿔서 검증합니다.

  • 규칙 하나는 이름, 기획서 문장, 측정 항목, 허용 범위로 구성
  • 허용 범위는 기획 판단이라 직접 정함. 기획서에 "약 N초"처럼 범위 없이 적힌 경우가 많아서, 현재 범위는 후보 중 하나를 임시로 넣은 값
  • 규칙 개수는 고정. 조건을 바꿔도 규칙은 그대로이고 일치, 불일치만 바뀜. 기획서에 새 의도가 생기면 규칙도 추가
  • 검증 규칙의 기획서 문장과 허용 범위는 대시보드 코드에 직접 들어가 있어서, DT 값이 바뀌면 함께 고쳐야 함

불일치 표시

  • 조건을 바꿔 실행할 때마다 실행 조건 목록에 한 줄씩 추가됨. 줄마다 바꾼 값과 불일치 개수가 표시되어 조건끼리 비교 가능
  • 불일치 개수를 누르면 불일치한 규칙이 펼쳐짐
  • 허용 범위에서 벗어난 정도를 색으로 구분. 개수만 보면 가벼운 불일치 여러 개가 심각한 불일치 하나보다 나빠 보일 수 있기 때문
  • 검증은 일치, 불일치와 벗어난 정도까지만 알려 줌. 불일치 하나에 여러 수치가 함께 관련되어 있어서 원인을 하나로 단정하지 않음. 원인은 값을 하나씩 바꿔 다시 실행하며 좁힘

데이터 처리

  • 시뮬레이션은 보는 사람의 브라우저 안에서만 실행되며, 서버와 LLM은 쓰지 않음
  • 수치 조정 패널에서 바꾼 값은 시뮬레이션에만 쓰이고, DT 문서와 게임에는 영향이 없음

분석하면서 발견한 점

  • 파훼 기록: DT 기본값 결과에서 파훼 횟수가 파훼 시도 횟수보다 많음(중간 봇 파훼 시도 1,850회, 파훼 2,259회). 봇이 돌진을 인지하기 전에 평소 하던 평타로 슈퍼아머가 깎인 경우가 섞여 있기 때문(중간 봇: 시도해서 파훼 1,786회, 인지 전 파훼 473회). 그래서 화면에는 두 경우를 나눠서 표시함
  • 카드 비교 착시: 고른 카드 전체로 비교하면 오래 버틴 플레이일수록 카드를 많이 고르므로 어떤 카드든 좋아 보임. 그래서 모든 플레이가 똑같이 고르는 1층 첫 카드 4장만 비교함. 그래도 카드마다 실력별로 14~55회뿐이라, 차이가 작은 값은 흐리게 표시함
